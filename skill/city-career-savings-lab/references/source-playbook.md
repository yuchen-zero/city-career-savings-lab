# 数据源与采集手册

## 先建来源矩阵

不要从一个搜索结果直接开始汇总。先为每个模块写明计划使用的来源、覆盖地区、统计期、平台可见性、计划样本量和证据等级，再开始采集。最低矩阵如下：

| 模块 | 首选 | 第二选择 | 不能替代 |
|---|---|---|---|
| 工资 | 城市统计公报、统计年鉴、人社工资价位 | 多个招聘平台的可复核广告样本 | 单篇晒薪、营销榜单 |
| 岗位供给 | 用户授权平台的城市/区县原始职位 | 企业官网、官方招聘会 | 只看搜索结果总数 |
| 工作条件 | 职位详情、平台结构化标签、企业招聘公告 | 面试/员工反馈访谈 | 未标注就假定无双休、不出差 |
| 房租 | 同城市同期间的租房挂牌样本、成交/租金指数 | 多个平台的区县样本 | 全国排名直接替代区县行情 |
| 水电气网 | 发改/住建/公用事业价格页 | 租客账单样本、合同附件 | 只用“每月约 100 元” |
| 餐饮 | 官方 CPI/居民消费支出 + 本地餐饮篮子 | 同城连锁/食堂样本 | 用外卖满减后的单次价格外推全月 |
| 通勤 | 官方票价、地图/交通规则 | 代表性路线实测 | 城市平均通勤时间替代具体居住-工作组合 |
| 税费社保 | 税务、人社、公积金官方规则 | 明确工资单/HR 口径 | 用全国统一比例假装精确 |

## 官方数据优先

对目标城市逐一搜索以下来源，优先使用政府或统计机构原始页面、PDF、年鉴和公报：

- 市统计局：统计年鉴、统计公报、国民经济和社会发展统计公报、居民收入和消费支出。
- 市人社局：人力资源市场工资价位、社保缴费基数、缴费比例、最低工资。
- 税务局：个人所得税政策、专项附加扣除、办理口径。
- 住房公积金管理中心：缴存比例、基数上下限、提取规则。
- 发改委/住建/城管/公用事业：水、电、燃气、供热、公共交通价格。
- 市/区县政府：人才补贴、租房补贴、落户、青年公寓政策。

检索词可按地区替换：`<城市> 统计年鉴 平均工资`、`<城市> 人力资源市场工资价位`、`<城市> 社保缴费基数`、`<城市> 公积金缴存比例`、`<城市> 居民人均消费支出`、`<城市> 水价 电价 燃气价`。

遇到 `data.stats.gov.cn` 或政府站点被 WAF、代理或网络环境拦截时，先确认是否为本地网络/代理问题；改走市政府和统计局原始页面、年鉴 PDF、公报附件。不要编造 API 结果，也不要把百度快照当成正式来源。把失败时间、错误页面或替代来源写入证据台账。

采集官方数字时必须同时抄下：指标名称、统计期、发布期、地区层级、单位、统计范围、样本/口径、表格或附件位置。`城镇非私营单位平均工资` 和 `全体居民人均可支配收入` 不能互相替代。

## 岗位平台

使用用户已经授权且能正常显示的浏览器会话。不得绕过验证码、风控、付费墙或平台访问限制，也不要把登录 Cookie 复制到聊天、CSV 或第三方服务。

### 查询设计

1. 先固定城市、学历、应届/经验不限、岗位族、双休、出差等可筛条件，再跑多个相近关键词，避免单一关键词造成行业偏差。
2. 每个关键词记录页码、搜索时间、筛选条件、结果数和实际采集数。搜索结果数是平台展示值，不是有效岗位数。
3. 如果总量超过可采集范围，先按城市/区县和岗位族分层，再在每个分层内抽页；不要只取前两页。
4. 同一天重复职位按职位 ID 去重；跨平台重复若无法确认，保留并标明 `duplicate_group`。
5. 记录广告中的薪资文字和年发月数。`8-20K`、`面议`、`13 薪`、`绩效另计`不能统一成一个“月薪”。
6. 将职位描述中的双休、出差、住宿、班制拆成结构化字段。`未写` → `unknown`；`明确不出差` → `none`；`偶尔出差` → `occasional`，不要合并。

### 去伪存真

对以下情况降低权重或复核，不要仅因薪资高就纳入：

- 薪资区间极宽、明显高于同城市同类岗位且描述非常模糊；
- 职位长期重复发布、多个账号转发、公司名称/地址不一致；
- 标题写“工程师”但职责主要是销售、电话营销、外包派遣或非目标专业；
- 入职条件写“培训后上岗”“先交费”“海外高薪”等高风险信号；
- 薪资文字与平台范围不一致，或者只展示最高值/计件上限；
- 只有一条或同一企业少数几条，不能代表城市。

最终报告应同时给出广告薪资中位数、四分位、岗位数、企业数和单一企业集中度；如有官方工资价位，作为外部分母并列，不强行拼成一个“综合平均”。

### 具体岗位查询

用户已经给出企业、完整岗位名、岗位链接或岗位编号时，不要机械重跑整套关键词。先直接打开原始招聘页或企业招聘系统；再按岗位编号、完整标题和地点查找企业官网及授权平台。搜索引擎摘要只用于发现入口，不能单独证明岗位存在、仍开放或薪资条件。

同一岗位的公司官网、ATS、校招平台和求职站转载应合并为一条岗位记录并保留全部来源链接；不同岗位编号、不同厂址或不同招聘主体要分开。岗位状态、专业可投性、双休、轮班、出差、驻场、住宿和薪资必须各自记录为“明确满足 / 明确不满足 / 未确认”，不能用一个标签替代。

完整字段、去重规则、岗位状态和单岗位交付结构见 [job-lookup.md](job-lookup.md)。

## GitHub 与现成采集工具

可以使用 GitHub 上的采集、清洗或可视化工具，但先做四步审查：

1. **许可证与用途**：确认允许当前使用方式，记录仓库、版本/commit、许可证和修改点。
2. **维护与依赖**：查看最近提交、issue、测试和依赖锁定；不要直接运行来路不明的二进制或安装脚本。
3. **数据权限**：确认不会绕过验证码、付费墙、登录限制或平台条款；不在第三方服务保存会话凭据。
4. **字段与可追溯性**：确认能保留原始 URL、职位 ID、采集时间、查询条件和页码；只有汇总结果、无法回溯原始记录的工具不适合作为证据主链。

先在隔离目录用单城市小样本试跑，检查输出字段、重复率、错误处理和中止行为，再决定是否进入正式项目。仓库里的示例数据、README 中的统计或作者结论都不是本项目的实证数据。

## 房租与租房费用

### 样本设计

- 城市级只用于初筛；城市内部按区县、板块和目标通勤圈继续分层。
- 整租和合租分开：整租记录面积、户型、朝向/装修至少一项；合租记录单间、公共区域和人数/房间数口径。
- 尽量固定时间窗（例如 30 天内）和面积/户型，避免拿豪宅与远郊隔断房比较。
- 每个区县至少记录有效挂牌样本数；样本不足时标 C 级，不做强排名。
- 挂牌价不是成交价，平台均价不是个人议价结果；在报告中分别命名。

### 费用拆分

每套房都尽量记录：月租、押金、预付月数、租客承担的中介费、月度服务费、一次性服务费、水电气网是否包含、物业费、取暖费、保洁费。格式示例：

```text
押一付三 = deposit_months 1, advance_rent_months 3
中介一个月 = agency_fee_months 1
首月租房现金 = 4 个月租金 + 中介费 + 一次性服务费
```

如果某城市常见“房东承担中介费”或“双方各付半月”，必须有当地页面、经纪人报价或用户访谈证据；不能把一线城市规则套到所有地区。

链家、贝壳、58、安居客等站点可能有验证码或反爬。遇到拦截就停止自动请求，换手动授权浏览、官方租赁平台、公开租赁指数或多个合法来源；不得规避验证码或批量抓取隐藏接口。

## 餐饮、水电气网和通勤

餐饮最容易产生虚假精确。至少分别记录早餐、午餐、晚餐或一个可复核的月篮子；外卖价格与堂食/食堂分开，考虑配送费、包装费、优惠券是否持续可得。官方居民消费支出可作为下限或交叉核验，但不能直接当成单身青年每月三餐支出。

水电气网优先使用当地价格文件，然后按人数、季节、面积和整租/合租制定用量假设；把单价、用量和分摊规则分别留痕。合租与整租不能使用同一个水电气数值。

通勤按具体居住区和工作区估算：公共交通票价、换乘次数、月票/折扣、步行时间和极端天气下的替代交通。城市平均通勤不能替代岗位所在区县的路线。

## 调研问卷

只有缺失字段会改变建模时才发问卷。建议控制在 8-12 个高信息量问题：

1. 目标地区/城市，是否愿意跨区县通勤；
2. 毕业年份、学历、专业和目标行业；
3. 明确排除的行业、企业或岗位；
4. 是否必须双休，能否接受轮班；
5. 出差偏好（不出差/偶尔/频繁均可）；
6. 是否接受现场调试、工程实施和设备驻场；
7. 整租/合租/公司宿舍，是否有同住人分担；
8. 是否由家庭承担首月押付、搬家或部分房租；
9. 薪资口径：税前/税后、固定/浮动、公积金是否计入可支配；
10. 每月可接受的房租上限、首月现金上限和最低净结余；
11. 最看重薪资、稳定、通勤、行业前景、落户/补贴中的哪几项；
12. 交付格式、数据截止日和可接受的估算范围。

用户勾选“有意排除”要保留原意，不能擅自改回“未勾选”。

## 采集记录

每个原始文件至少记录：

```text
module=jobs|rent|living|payroll|official
city=...
query=关键词/筛选条件
source=...
url=...
collected_at=YYYY-MM-DD HH:MM
period=统计期/挂牌期
sample_n=...
raw_file=相对路径
```

没有 URL 或原始文件的数字可以用于探索，但不能作为报告中的单独证据。遇到网站改版、限流或反爬，先记录失败状态和已完成覆盖，再继续其他模块；不要为了凑满城市而重复抓同一页。

## 停止条件

达到以下任一条件即可先出阶段性结论，而不是无限扩展：

- 关键模块已有可复核样本，且新增来源不再改变主要排序；
- 目标城市/区县的岗位与房租证据达到预设最低样本；
- 继续采集会触发明显限流、法律/平台限制或成本超过任务价值。

阶段性报告必须把“未覆盖城市/区县、样本时间窗、缺失模块、未核实标签”写在限制部分。
