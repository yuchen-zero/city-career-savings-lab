# 应届生城市调研

## 目标

把“某专业应届生去哪个城市/区县工作更合适”转化为可复核的数据问题。最终结论至少同时考虑：目标岗位供给、税前招聘薪资与税后现金、双休和出差等硬条件、整租/合租、水电气网、餐饮、通勤、押付和渠道费、首月现金压力，以及证据质量。不能把招聘广告中的最高薪资直接当作可支配收入。

当用户已经锁定某家公司、某个岗位、岗位链接或岗位编号时，切换到“具体岗位查询与核验”模式；不必先跑城市全量采集，也不能把岗位搜索结果数当作供给样本。

## 不可妥协的规则

1. **每项关键数字可追溯。** 至少保存 `source_url`、`collected_at`、统计口径、地区、样本量和证据等级；派生值保存原始字段或公式版本。
2. **不补造缺失值。** 找不到数据就写“未取得”，并用区间、保守假设或敏感性分析处理。不得把模型估计包装成实测。
3. **先官方、再平台、后个体样本。** 官方统计、税务、社保、公积金和价格规则优先；招聘平台适合岗位和广告薪资；个人晒薪只作 C/D 级旁证。
4. **严格区分口径。** 招聘广告税前月薪、固定月薪、年包、现金到手、含公积金收入、公司总成本不能混用。招聘薪资默认是广告值，不等于真实员工中位数。
5. **保留用户硬约束。** 有意排除的行业/雇主、双休、出差、住宿、租房方式和独居/家庭支持必须单独建模；未填写不等于不要求。
6. **小样本不参与强排名。** 同时展示岗位数、企业数和最大企业占比；样本少、单一雇主主导、只有短期挂牌价时，只能给观察值，不能下确定性结论。
7. **只采集合法可见数据。** 可使用用户已授权的登录会话；不得绕过验证码、付费墙或访问控制，不保存账号密码。遇到限流就降速、拆分任务、记录缺口，等待或换合法来源。
8. **结论必须可被更保守的情景推翻。** 至少比较合租/整租、直租/中介/品牌公寓、纯现金/含公积金，并说明排序在什么条件下改变。
9. **具体岗位按“岗位身份”去重。** 同一岗位编号、同一原始招聘页及其转载属于一个岗位；多个平台同时出现不等于多个招聘名额。没有原始页或稳定编号时，必须标注匹配置信度。
10. **招聘状态与岗位条件分开判定。** 搜索结果仍显示、页面能打开、申请按钮可用或 HR 口头回复，都不能自动等同于岗位仍开放或某项条件已经书面确认；`unknown` 既不算满足，也不算不满足。

## 工作流

### 1. 定义研究问题

开工前只问会改变结果的变量：目标地区、届别和专业、目标行业/岗位、明确排除项、必须双休或出差偏好、租房方式与人数、是否有家庭资助、薪资口径、数据截止日和交付格式。能从已给材料推断的不要重复询问。

先把问题写成一句决策句，例如：“2027 届某专业本科应届生，在某区域哪些城市/区县的税后净结余、岗位供给和工作条件综合最好？”

### 1A. 查询或核验一个具体岗位

读取 [references/job-lookup.md](references/job-lookup.md)，按其中流程执行。最低输入应尽量包含：企业名称、完整岗位名、工作地点、届别/学历/专业；若用户提供岗位链接、岗位编号、招聘截图或经办平台，一并保留。缺少某一项时先做候选匹配，只有不同候选会改变结论时才请用户确认。

单岗位查询默认交付一页式“岗位核验卡”，优先回答：是否找到原始岗位页、岗位是否仍开放、是否匹配 2027 届本科及目标专业、广告薪资/年发月数、双休/轮班、出差/驻场/现场实施、住房与班车、工作地点、证据日期、仍缺信息和向 HR 核验的问题。不要为了凑成城市报告而虚构同岗位样本或薪资中位数。

### 2. 初始化可复核项目

```text
python scripts/research_workbench.py init --output <项目目录> --region <地区> --major <专业> --graduate-year <年份> --cities <城市1,城市2>
```

该命令生成 `config.json`、岗位、城市模型、原始房租、生活成本、工资制度、官方薪资和证据台账 CSV，以及 `sources/raw`、`output` 目录。字段定义见 [references/data-contract.md](references/data-contract.md)。

### 3. 采集并建立证据链

按 [references/source-playbook.md](references/source-playbook.md) 选择来源、构造查询、抽样和保存原始证据。每个模块至少回答：来源是谁、覆盖什么、何时采集、统计期是什么、样本多少、是否为挂牌/广告/实际支付、哪些人没有覆盖。

招聘采集先保存原始记录，再做标准化。不要用公司宣传页、聚合站转载或“网传薪资表”替代原始来源。官方数据缺失时标注缺口，不用单条帖子补齐。

开跑全量前先做小规模烟测：同一城市 1-2 个关键词、少量职位详情、一个区县的整租与合租各一页。核对登录态、字段、去重、限流、断点续跑和原始文件保存是否正常，再扩大范围。使用 GitHub 工具前先审查许可证、维护状态、依赖和数据权限；工具只是采集手段，不能成为数据来源。

在采集前说明数据保存在哪个本地项目目录、哪些原始文件会保留、是否会包含个人信息。代用户操作已授权的浏览器会话时，不导出或上传 Cookie、密码和验证码。

### 4. 清洗、去重和结构化

岗位至少标出城市、区县、岗位族、学历、经验、薪资上下限、年发月数、双休、出差、住宿和企业标识。对重复职位、猎头转载、实习/兼职、专业无关岗位和非目标地区建立可复现的剔除规则。

房租至少区分城市/区县、整租/合租、面积或房间口径、押金、预付月数、中介费、服务费。生活成本至少包含餐饮、水费、电费、燃气、网络、通勤和必要固定支出。工资制度至少记录社保、公积金、个税口径及数据年份。

### 5. 计算净结余和首月现金

```text
python scripts/research_workbench.py validate --project <项目目录>
python scripts/research_workbench.py jobs-summary --project <项目目录>
python scripts/research_workbench.py calculate --project <项目目录>
```

`validate` 检查字段、重复、日期、异常值和小样本；`jobs-summary` 按城市/区县/岗位族输出岗位数、企业集中度、薪资四分位和工作条件计数；`calculate` 输出月均现金净结余、含公积金净结余、房租负担率和首月现金。

核心口径：

```text
月均现金结余
= 年化税后现金收入 / 12
- 房租 - 中介费摊销 - 月度服务费 - 水电气网
- 餐饮 - 通勤 - 其他固定支出

含公积金结余 = 月均现金结余 + 个人公积金月缴额

首月现金 = 房租 ×（押金月数 + 预付月数 + 中介费月数）
          + 一次性服务费 + 其他一次性支出
```

社保、公积金和个税优先使用目标城市当年官方规则；暂时拿不到时，在 `city_model.csv` 填明确输入的月扣款或 `monthly_cash_override`，并在报告中说明。不要把统一比例当成精确承诺。

### 6. 分析和排序

先按硬条件过滤，再比较净结余。每个城市/区县展示：有效岗位数、企业数、薪资中位数及四分位、工作条件命中率、整租/合租成本、首月现金、净结余、房租收入比、证据等级和主要缺失。

至少做三组敏感性分析：整租 vs 合租、现金 vs 含公积金、不同工资/房租/餐饮假设。若排名只相差数百元或低于数据误差，写“并列/无法区分”，不要制造精确名次。区县推荐不能只看高薪或低房租，还要看该区县目标岗位是否足够多。

### 7. 输出和验收

除非用户另有要求，交付 Word 报告、Excel 总表和自包含交互式 HTML。结构、图表和验收项见 [references/deliverables-and-audit.md](references/deliverables-and-audit.md)。

交付前必须完成：

- 所有关键结论能回到数据表和来源台账；
- 复算样例通过，公式列不因插列/排序漂移；
- 城市、区县、薪资、租期、税费和成本口径没有混用；
- 搜索结果数量不是有效样本数量；
- 报告明确写出截止日期、样本偏差、缺失数据和会改变结论的条件；
- Word 表格无跨页截断，Excel 无断链，HTML 离线可打开且切换参数后结果一致。
